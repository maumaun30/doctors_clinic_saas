# web — doctors_clinic_saas

Next.js 15 (App Router) + TypeScript + Supabase (`@supabase/ssr`).

## Setup

```
cd web
npm install
cp .env.example .env.local   # fill in URL + anon + service_role
npm run gen:types            # regenerates lib/database.types.ts from local Supabase
npm run dev
```

Set OAuth redirect URLs in the Supabase dashboard to:
`http://localhost:3000/auth/callback` (and your prod equivalent).

## Layout

```
app/
  layout.tsx           root
  page.tsx             /  -> redirects by role
  (auth)/login         OAuth buttons (Google; Apple/Facebook disabled)
  auth/callback        OAuth code-exchange route handler
  (app)/layout.tsx     authed shell + nav, role-gated
  (app)/pending        awaiting-approval screen
  (app)/schedule       appointment list
  (app)/patients       patient list + [id] detail (medical records)
  (app)/visits/[id]    doctor: complete appointment + write record
  (app)/admin/         clinics, doctors, secretaries, assignments, users
middleware.ts          session refresh + auth gate
lib/
  supabase/{browser,server,admin}.ts
  data/queries.ts      framework-agnostic queries (Expo will reuse)
  schemas/index.ts     Zod input schemas
  actions/             Server Actions wrapping RPCs (book / complete / assign)
  database.types.ts    generated by `npm run gen:types`
```

## Trust boundary

- `lib/supabase/browser.ts`, `lib/supabase/server.ts` → use the **anon**
  key + the user session. RLS does the gating.
- `lib/supabase/admin.ts` → service_role, marked `server-only`. Used only
  for things RLS can't (none in MVP — left as a seam for future
  back-office tasks).
- All RPCs (`book_appointment`, `complete_appointment`, `admin_assign_user`,
  `list_pending_users`) authorize via `auth.uid()`, so they're safe to call
  from a session client.
